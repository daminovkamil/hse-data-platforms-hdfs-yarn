# ДЗ №3 — Hive

Цель: удалённый Hive Metastore в PostgreSQL, HiveServer2 для нескольких
одновременных Beeline-клиентов и повторяемая загрузка данных в
партиционированную таблицу.

Используется Hive 4.2.1, а не рекомендованный в задании 4.0.0-alpha-2:
это [стабильный выпуск](https://hive.apache.org/general/downloads/), для
которого Apache указывает совместимость с Hadoop 3.4.1. Для Hive требуется
Java 21; HDFS и YARN из ДЗ №1–2 продолжают работать на Java 11.
`setup.sh` копирует Hadoop XML-конфигурацию для Hive и задаёт в ней отдельный
`JAVA_HOME`, не меняя настройки работающих HDFS/YARN-демонов. Hive 4.x не
является поддерживаемым
metastore-клиентом Spark 3.5, поэтому в ДЗ №4 обмен данными идёт через
Parquet в HDFS, а регистрацию таблицы выполняет штатный клиент Hive.

## Развёртывание

На главной VM должен работать HDFS и YARN из предыдущих заданий. Для
Hive-заданий на YARN установите Java 21 на трёх рабочих VM (после ДЗ №2):

```bash
bash hw3/prepare-worker.sh
```

Затем на главной VM выполните команды ниже. Нужен доступ `sudo`, а между
VM должны быть разрешены внутренние TCP-подключения
к портам 9083 и 10000. В Интернет эти порты не открывать: HiveServer2
в учебной конфигурации не аутентифицирует клиентов. Запросы выполняются
от пользователя HiveServer2, без разграничения прав между клиентами.

```bash
bash hw3/setup.sh
bash hw3/start.sh
bash hw3/load.sh
bash hw3/check.sh
```

`setup.sh` устанавливает PostgreSQL и Java 21, скачивает Hive с проверкой
SHA-256, создаёт отдельную БД metastore и инициализирует схему только если
она ещё не существует. Пароль БД генерируется в `hw3/metastore.password`
(не отслеживается Git); его и `hivemetastore-site.xml` нужно хранить только
на главной VM с правами 600. Сам пароль клиентам не передаётся.

`load.sh` загружает `events.csv` в HDFS и через HiveServer2 выполняет
`load.sql`: внешняя таблица читает CSV, а результат сохраняется как
партиционированная по `event_date` таблица Parquet. Повторный запуск
перезаписывает её содержимое, не создавая дубликатов. Ожидаются 5 строк
и две партиции (`2026-10-20`, `2026-10-21`). `check.sh` запускает два
Beeline-клиента одновременно и проверяет результат каждого.

Для проверки доступа второго клиента установите Hive Beeline на другой VM
или используйте клиент с главной VM в отдельном терминале:

```bash
beeline -u 'jdbc:hive2://MASTER_HOST:10000/default' -e 'SELECT COUNT(*) FROM hse_hw.events;'
```

Замените `MASTER_HOST` на внутренний адрес из `cluster.env`. Этот клиент
можно запустить во время выполнения `check.sh`.
