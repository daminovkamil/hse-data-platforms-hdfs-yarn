# ДЗ №4 — Spark на YARN

Spark 3.5.8 запускается на YARN-кластере из ДЗ №2. Программа читает CSV
из HDFS, явно преобразует типы, проверяет некорректные строки,
группирует события по дате и типу, считает количество и сумму и
сохраняет Parquet, разбитый по `event_date`. Затем Beeline регистрирует
эти файлы как внешнюю таблицу Hive и восстанавливает список партиций.

Такой обмен через HDFS нужен потому, что [Spark 3.5 официально поддерживает
metastore до Hive 3.1.3](https://spark.apache.org/docs/3.5.8/sql-data-sources-hive-tables.html),
а в ДЗ №3 используется Hive 4.2.1. Подключение Spark напрямую к этой версии
metastore не объявляется поддерживаемым.

## Запуск

На главной VM после ДЗ №3:

```bash
bash hw4/setup.sh
bash hw4/run.sh
bash hw4/check.sh
```

`setup.sh` скачивает Spark с проверкой SHA-512. `run.sh` использует Java 11
для Spark и Java 21 для Beeline, устанавливает `HADOOP_CONF_DIR`, запускает
`spark-submit --master yarn --deploy-mode client` с двумя executor'ами и
регистрирует результат через HiveServer2. Driver доступен worker-узлам по
внутреннему адресу главной VM; порты 7078 и 7079 должны быть открыты только
между четырьмя VM. Рабочим VM потребуется не менее 2 ГБ RAM каждая.

После проверки должны появиться партиции `event_date=2026-10-20` и
`event_date=2026-10-21`. Ожидаемые строки (порядок по дате и типу):

| event_date | event_type | event_count | total_amount |
| --- | --- | ---: | ---: |
| 2026-10-20 | purchase | 1 | 120.5 |
| 2026-10-20 | view | 2 | 0.0 |
| 2026-10-21 | purchase | 2 | 120.25 |

Проверка идёт стандартным клиентом Hive (`beeline`), а не Spark SQL. Таблица
внешняя: удаление её метаданных само по себе не удаляет Parquet-файлы в HDFS.
